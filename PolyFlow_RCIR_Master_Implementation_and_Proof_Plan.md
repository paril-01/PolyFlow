## B. Architecture and scope

### B1. Proposed minimum product architecture

1. Repository snapshot manager: canonical repo identity, Git commit/tree, tracked-file manifest, raw hashes, optional normalized-text identity with declared version, mutable overlay version, parser/index config and permissions. Never substitute HEAD string for resolved SHA. Refuse ambiguous or dirty snapshots unless explicit overlay is captured.
2. Language-aware indexing: reuse canonical entity registry, typed graph, graph adapters, ranker, planner, source resolver and tokenizer. Symbol identity includes language, namespace, path and scope. Store exact parsed spans, relation evidence and resolution states (exact/inferred/ambiguous/unresolved). Use robust parsers/LSP where appropriate; regex is candidate discovery only. Index supported languages and declare unsupported cases. Lexical retrieval is a strong fallback with honest provenance, not a failed graph arm masquerading as a graph result.
3. Retrieval: resolve change intent, generate lexical and graph candidates, expand relevant typed edges with hop/size bounds, rank by target identity, operation, evidence quality, graph distance and test relevance; deduplicate overlapping spans; pin critical source; report omissions and uncertainty. Test R0, repaired R1, R2, and R3 hybrid (lexical seeds + canonical graph + versioned evidence) under identical candidate budgets. Prefer measured Pareto frontier over novelty.
4. Evidence store: source-bound records, reverse dependency edges, cycle-safe closure, incremental update/delete/rename/reparse and generation-based atomic publication. Invalidate dependent cached bundles and session state. Compare incremental index with clean rebuild for every mutation sequence. Store read-only immutable originals with scoped handles; separate canonical graph truth from delivery hints.
5. Context delivery: exact evidence plane and supplementary plane. Route only eligible logs, repeated search output, JSON and diffs through optional Headroom adapter. Preserve original bytes/hash, marker and retrieval handle; mark views lossy versus lossless. No transformed code as patch coordinates or exact evidence. Protect user/system instructions, test results, security information, essential source spans and identifiers. Keep original available, never claim availability after eviction. Fail open only for authorized supplementary data that fits budget; otherwise return explicit budget/availability error. Evidence validation fails closed.
6. Session and cache: exact snapshot/overlay/tenant/policy/tokenizer/query/algorithm version keys, bounded LRU/TTL, no reuse across trials, stable prefix for unchanged evidence when client/provider supports it. Client-visible stale references must be invalidated. Do not confuse provider prompt-cache discount with token reduction or local cache hits.
7. Read-only SDK + MCP service: verified tool registration/transport, `rcir_context_retrieve`, `rcir_evidence_expand`, `rcir_impact_analyze`, `rcir_status` (names proposed). Typed responses, schema compatibility, cancellation, resource budgets, local-only default, permission checks on each call, no shell/write authority. Agent tools/editing remain separate; AEF remains independent. Package a documented installable Python distribution and CLI, with optional compression dependency and rollback switch.
8. Instrumentation: request-level actual provider token receipts, tool-delivery exact/estimated counts separately, cost schedule and cache counters, CPU/RSS/index/retrieval timings; signed or hash-bound append-only run manifest, patches, test results and independent recomputation. Never call a hash a signature; signing optional with real key custody.

### B2. Headroom adoption (after correctness baseline)

Upstream: https://github.com/headroomlabs-ai/headroom ; [architecture](https://github.com/headroomlabs-ai/headroom/blob/main/docs/content/docs/architecture.mdx), [CCR](https://github.com/headroomlabs-ai/headroom/blob/main/docs/content/docs/ccr.mdx), [limitations](https://github.com/headroomlabs-ai/headroom/blob/main/docs/content/docs/limitations.mdx), [license](https://github.com/headroomlabs-ai/headroom/blob/main/LICENSE). Prefer optional public SDK adapter over vendoring. SDK does not automatically provide the proxy's full CCR tool loop: explicitly wire authorized retrieval or use the proxy in a separately measured arm. Disable analytics/remote inference for local experiments; verify by network-denied tests. CacheAligner is a detector in current docs, not automatic prompt rewriting. Current code compression is opt-in; leave disabled initially. TOIN-inspired learning only after benchmark: train on DEV and independently verified usage; never change graph truth or tune on locked data. Compare deterministic cheap transforms with Headroom itself; native Rust acceleration only if profiling demonstrates need.

## C. Benchmark design: prove four distinct things

### C1. Test tracks

**T0 Integrity and lifecycle.** Unit/property tests for hashes, resolver certainty, bounds, cache invalidation, security and deterministic behavior. Cross-OS CI. Real source snippets for integration, synthetic adversarial fixtures labeled. Not a product speed claim.

**T1 Repository retrieval, no LLM.** Real tasks from pinned repository snapshots, evaluator-authored acceptable target spans, dependency edges and critical evidence sets; score exact file/symbol/span/edge recall and precision, critical evidence recall, nDCG@k, MRR, ambiguity handling, source fidelity, token budget adherence, query p50/p95, index time/RSS/disk and incremental update cost. Use 1k/2k/4k/8k shared tokenizer budgets including envelope/metadata. Retrieval query is natural-language issue only (public path hints only if legitimately in original issue, same for all arms); no hidden expected path. Report critical recall vs token budget curves and minimum budget to achieve matched recall. Exact normalized path equality and span overlap rules, no substring scoring. Define missing/empty target cases explicitly. Compare cold and warm separately, include graph build cost and reusable indexing amortization. No API spend necessary.

**T2 Trace replay / compression.** Capture tool-result traffic from actual authorized DEV and held-out runs: original search results, logs, diffs, JSON. Replay identical traffic through no transform, Headroom, RCIR delivery and combined, preserving message semantics. Use actual tokenizer for full serialized provider requests where supported, count tool schemas, retrieval markers and expansion costs. Validate critical content byte preservation and reconstruction; ask fixed independently verified questions when claiming semantic preservation. Replay compression counts are NOT equivalent to actual LLM billing or actual edit success. Publish separate numbers for eligible payloads and total requests. Report p50/p95 transform latency, bytes, storage and retrieval frequency. Headroom reported savings are not ours.

**T3 Paired historical change reconstruction.** The strongest evidence for coding utility: real base commit before a merged fix/feature, public issue description available before the fix, original upstream solution evaluator-only. Same base snapshot, agent, prompt, standard tools, budgets, settings and test environment for all arms. Agent produces its own patch; independent evaluator runs behavioral fail-to-pass and pass-to-pass tests, compilation/security checks and hidden regression tests. Exact diff match is not required; alternate valid implementations pass. Save patches and logs. Include no-edit diagnostic tasks separately with a verifier expecting zero modifications; do not judge them by generic nonempty-diff rules. Include actual ongoing fresh tasks independently authored against current snapshots to mitigate training memorization. Historical tasks are not guaranteed unseen by the LLM; disclose contamination risk, prefer post-known-cutoff tasks where possible, never claim guaranteed blind model knowledge.

**T4 Native IDE/plugin effectiveness.** Real IDE A/B sessions with native search/index/tools enabled in both, RCIR MCP only added to treatment. Optional Headroom proxy in a third/fourth arm where supported. Run separate randomized fresh sessions, same model/account/settings, verify actual MCP tool calls from receipts and record client version. No simulated IDE credit counts. If native IDE usage unavailable, publish measured MCP usage and verified task success; IDE token/credit savings NOT_MEASURED. A controlled API/local benchmark cannot be relabeled native IDE evidence.

### C2. Task sourcing and feasibility

Start with Nextcloud (`https://github.com/nextcloud/server`, existing pinned SHA `da57df078d0808a7235a0177bd99d23c010b472e`) to reproduce and debug; its historical tasks are DEV only. Existing `.gitmodules` includes https://github.com/pallets/flask, https://github.com/psf/requests, https://github.com/open-telemetry/opentelemetry-demo. Choose Flask or Requests for fast toolchain calibration and independently sampled Python tasks; Nextcloud for PHP/JS/TS boundaries; OpenTelemetry demo or https://github.com/GoogleCloudPlatform/microservices-demo for actual cross-service/multilanguage tasks after build/test feasibility. Optionally ERPNext for later enterprise validation, not a prerequisite. Candidate repositories are suggestions, not verified ready-to-run task banks. Resolve exact SHAs, license, history, issue and test feasibility before freezing. Use existing official SWE-bench resources (https://github.com/SWE-bench/SWE-bench) as supplementary external comparison with its own protocol; it is not sufficient alone for polyglot proof and public tasks can be memorized.

Avoid upgrading an entire repository to a release: too many unrelated changes, expensive tests, unclear equivalence. Sample bounded actual historical PRs instead. For each task maintain an evaluator-only `task_id, repo_url, base_sha, fix_sha, issue_url, public_prompt, source_license, container_digest, dependency_lock, allowed_paths, must_change/no_edit, reference_patch_hash, fail_to_pass_ids, pass_to_pass_ids, critical_spans, relation_labels, hidden_tests_hash`. Public input contains only task ID, base identity, prompt, available commands and public constraints. Freeze DEV/VALIDATION/LOCKED splits by issue family and repository/time; keep duplicates and shared fix families out of different splits. Proposed pilot 6 tasks across 2 repos, then validation 12–20 tasks, then final 60 locked tasks across at least 3 repos (20 per repo where feasible) with 2 replicates. Pre-register actual sample and budget after DEV power/variance estimation; 60 is not automatic statistical adequacy. Publicly committed old task IDs and labels never enter new locked set. Independent curator signs off on eligibility before agent runs; record exclusions and why.

### C3. Comparison arms

Retrieval study: R0 repaired lexical/symbol/BM25, R1 repaired canonical graph, R2 VEST-lite, R3 hybrid; ablate lexical, graph, ranker, incremental store, context packer separately on DEV. All use identical visible snapshot and budget, language scope, evaluation oracle and tokenizer. R0 is not intentionally weak; include rg/symbol/LSP where appropriate and disclose dependencies. If simpler wins, retain it; graph may still be beneficial only on dependency-heavy strata.

Live study factorial: A = native/conventional tools only (strong baseline), B = same + RCIR, C = same + Headroom, D = same + RCIR and Headroom. Same edit/read/search/test tools available in all arms; no prefilled answers; extra retrieval/compression is treatment. A vs B is RCIR contribution, A vs C Headroom contribution, B vs D incremental compression, C vs D incremental RCIR under compression. Randomize/counterbalance execution order by task/replicate; separate workspaces, sessions, cache namespaces, no learning across arms, no retries cherry-picked. Keep actual model version, temperature/reasoning/tool schemas, provider max context and request limits identical except treatment; if seed unsupported record it. Same max turns, wall time, input/output/spend budget and tool calls where meaningful. Use independent agent runner outside RCIR. Estimate cost from DEV before owner authorization. Local option: test available models on DEV; 1.5B already historically struggled; choose a stronger feasible local coder model based on actual hardware and license, not a hardcoded model name. No paid APIs by default. 60 × 4 × 2 = 480 planned trials, before retries or setup; if budget limited, prioritize A/B then C/D on a preregistered subset, and state comparison scope.

### C4. Isolation and test qualification

Evaluator checks base: targeted test must fail for intended assertion, not dependency/compile/timeout/setup error. Reference fix must pass targeted and regression checks in identical environment. Baseline existing tests pass. Reject ambiguous or flaky tasks before freeze using declared rules. Use real upstream tests plus independently authored behavioral tests for edge cases; no string search for patch correctness. Snapshot only the base tracked files for agents (or isolated fresh Git history that contains no future objects/remotes). Keep reference commits, private test code, labels, answer diffs outside agent-visible filesystem, tool routes, RCIR index, model context, caches and network; evaluator gets candidate patch via narrow interface. OS-level sandbox: unprivileged, read-only evaluator, network disabled, restricted environment/secrets, CPU/RAM/time/process limits, no host mounts, allowlisted tools. Avoid shared Git worktree metadata for blinded trials. Index per trial and refresh after edit events. Save full patch including staged/unstaged/untracked/deletes/renames, final tree hash, execution/test logs and usage. Do not expose hidden test content during agent execution. Never mark setup errors pass. Use deterministic test seeds and repeat baseline tests to identify flakes. No silent rerun of failed agent attempts. Infrastructure retries governed by preregistered policy, retain all receipts.

### C5. Metrics and proposed release criteria

Primary utility: verified success per assigned eligible task/trial (intention-to-treat; failure/timeouts/RCIR setup failure count against treatment unless a preregistered arm-independent setup exclusion). Compare paired success difference and task-cluster bootstrap 95% interval; report discordant outcomes, exact paired test as appropriate, stratify by repo and complexity. Replicates are clustered within task, not independent tasks. Primary efficiency: total provider-native input tokens per assigned trial (include failed attempts/expansions/retries/tool schema/history), plus tokens per successful completion = aggregate input tokens / number of independently verified successes, undefined if zero. Both-successful paired median/ratio is secondary, susceptible to survivor selection; report sample and intervals. Input savings = 1 − sum(Treatment input)/sum(Baseline input), only comparable measured runs; missing usage is unknown, not zero. Report output/reasoning tokens as provided without double counting, cached input (subset vs separate field per provider), billable cost using actual date/model rates, wall time, local prefill time if measured, indexing and runtime overhead, tool calls and bytes. Never conflate context bytes/token estimates, actual provider tokens, billable tokens and IDE credits. Real $ cost not meaningful for local inference unless measuring electricity/hardware separately. Report no paid API spend if none, not zero compute cost.

Proposed preregistration criteria (engineering targets, not achieved results):
- T0: required CI jobs green on supported Linux/Windows, 0 known critical provenance or isolation defects, 100% exact source-byte validation for delivered `STATIC_EXACT`, 0 verified stale evidence delivered as fresh, 0 strict budget violations; no prohibited path access; invalidation closure equals clean rebuild for declared supported mutations.
- T1: candidate must exceed or be noninferior to R0 on critical evidence recall (predeclared margin 2 percentage points), aim ≥95% critical recall on supported locked tasks at 4k; no falsely exact edges in audited sample; target p95 warm retrieval ≤500ms or ≤R0 + approved overhead on stated hardware, plus report cold/index/RSS. Choose based on quality first then Pareto tradeoff. If thresholds infeasible revise only before locked evaluation, record rationale.
- T2: 100% protected content preservation and successful restoration where declared available; target ≥15% reduction in all-input replay tokens over B for combined when applicable, not just eligible payload. Separate workload-specific effects. Cache misses/evictions explicit.
- T3: preregister noninferiority margin (suggest −5 percentage points for verified task success) and demonstrate confidence interval lower bound above margin for release claim; target ≥15% actual input reduction, with 95% interval excluding zero, and no worse tokens/success or critical regression rate. Target ≥70% verified success on a qualified benchmark/model or comparable strong baseline, with minimum both-successful pairs (suggest 30 distinct tasks) for secondary estimate. If sample insufficient, INCONCLUSIVE, not PASS. A stronger claim (higher success and lower cost) requires evidence for both. No production claim from 3 successful pairs. Tune margins/sample only on DEV, freeze before locked. Report every repo/category, failed and invalid trial, exact sample and uncertainty.
- T4: actual third-party installation and invocation, same IDE settings for arms, independently verified task patches and reproducible logs. Native token/credit reduction claim only with native attributable telemetry. No proxy interception of unauthorized traffic.

Stop if integrity gates fail; no UI marketing percentage. If RCIR cannot meet targets, publish negative findings, diagnose on DEV and evaluate next release on a fresh held-out cohort. No locked-set retuning.
