## 1. Executive Summary

A comprehensive forensic audit of the PolyFlow codebase, benchmark harnesses, telemetry pipelines, and visualization layers was conducted against the historical baseline (commit `3a29cebe9732f91c60d4dd78844d8a5d0039104e` and subsequent HEAD commits).

Sixteen specific defects across experimental rigor, statistical integrity, harness accounting, security boundaries, and UI presentation were identified. Every defect has been traced to its exact source location, its root cause diagnosed, code corrections applied, and automated regression verifiers implemented.

## 2. Defect Matrix & Rectification Details

### Finding 01: RCIR Arm Used Prompt Decoration Instead of Concrete Context Retrieval
- **Severity:** Critical (P0)
- **Source Path:** `experiments/final_blind_validation/run_blind_benchmark.py`
- **Root Cause:** The blind benchmark runner passed only a generic textual tier hint (`"Target file is in Tier 1..."`) to the agent prompt in the RCIR condition, without invoking `ConcreteRCIRContextProvider`, `ContextCompiler`, or the underlying repository dependency graph.
- **Correction Applied:** Integrated `ConcreteRCIRContextProvider` from `experiments/rcir_v8_5/scripts/run_agent_validation.py`. The runner now instantiates the live graph, compiles structural AST/dependency context into `ContextRetrievalResult`, and injects the genuine retrieved context block into the agent's tool environment and system prompt.
- **Regression Test:** `tests/test_final_claim_consistency.py` verifies that the RCIR condition calls the live context provider and passes genuine graph context.

### Finding 02: Synthetic "After-Fix" Data Copied from Baseline Trials
- **Severity:** Critical (P0)
- **Source Path:** `experiments/final_blind_validation/generate_after_fix_and_delta.py`
- **Root Cause:** `generate_after_fix_and_delta.py` previously duplicated `baseline_data["trials"]` directly into `after_fix_data["trials"]` and applied simulated token adjustments rather than running a fresh, isolated execution.
- **Correction Applied:** Replaced synthetic copying with strict execution provenance. `after_fix` data must either be generated by a real secondary runner execution with unique run IDs, timestamps, and worktree traces, or transparently marked `HISTORICAL_UNVERIFIED`.
- **Regression Test:** `tests/test_final_claim_consistency.py::test_no_synthetic_after_fix_duplication` verifies that `after_fix` trials do not share identical run timestamps and trace signatures with baseline trials.

### Finding 03: Mislabeled Valid Pairs (Timeouts Counted as Valid Pairs)
- **Severity:** High (P0)
- **Source Path:** `experiments/final_blind_validation/results/blind_baseline.json`, `rcir/visualizer-react/public/data/token_ab.json`
- **Root Cause:** In a 5-task, 10-trial benchmark run, 2 trials on `qwen2.5-coder:1.5b` timed out. The baseline runner correctly logged 3 valid pairs and 0 successful pairs, but presentation layers and summaries reported "5 valid pairs (100% completion)", conflating attempted pairs with valid completed pairs.
- **Correction Applied:** Hardened valid pair accounting: a trial with `error == "TIMEOUT"` is classified as `INVALID_PROVIDER_TIMEOUT`. A pair is valid IF AND ONLY IF both baseline and RCIR arms complete without runtime, tool, or timeout errors (`valid_pairs: 3`). Token reduction percentages are computed strictly over `VALID_PAIR` entries.
- **Regression Test:** `tests/test_final_claim_consistency.py::test_valid_pairs_accounting` asserts that trials with timeouts cannot be marked as valid completed pairs.

### Finding 04: Baseline Execution Chronology Contradiction
- **Severity:** Medium (P1)
- **Source Path:** `experiments/final_blind_validation/results/blind_baseline.json`
- **Root Cause:** The baseline results claimed to represent the pre-fix state prior to the `os` import crash fix, but timestamps confirmed they were collected after the patch was committed.
- **Correction Applied:** Reclassified historical trial datasets with accurate lineage: historical runs are archived under `pre_fix_historical/`, while current runs are scoped to unique run IDs under `experiments/runs/<run_id>/`.
- **Regression Test:** Provenance metadata checks in `scripts/build_showcase_data.py`.

### Finding 05: Inconsistent Frozen Test-Design Hashes
- **Severity:** High (P0)
- **Source Path:** `experiments/final_blind_validation/manifest.json`, `experiments/final_blind_validation/test_design.json`, `reports/BLIND_AFTER_FIX_REPORT.md`
- **Root Cause:** Modifications to task descriptions in `test_design.json` caused its SHA-256 hash (`6143ff80a7d854b6cee749deb09bea8c88d5b6a29ee70da0b561cbfe4116b265`) to diverge from references in `manifest.json` and Markdown reports which still referenced older hashes.
- **Correction Applied:** Synchronized the canonical test design hash across all manifests, reports, and assertions using dynamic hashing `sha256(test_design.json)`.
- **Regression Test:** `tests/test_final_claim_consistency.py::test_test_design_hash_integrity` verifies exact equality across all manifests and reports.

### Finding 06: `verify_regression.py` Representing PHP Syntax Checks as L3 Regression
- **Severity:** High (P0)
- **Source Path:** `experiments/rcir_v8_5/agent_tasks/verify_regression.py`
- **Root Cause:** When running on modified Nextcloud files, the verifier executed `php -l` (syntax check) and reported the result as an "L3 Regression Suite Pass". Furthermore, if 0 files were modified, it fell back to checking 5 hardcoded core files and reported a pass.
- **Correction Applied:** Categorized verifiers into three strict tiers: `L1_SYNTAX` (`php -l`), `L2_BEHAVIOR` (targeted task tests), and `L3_REGRESSION` (full upstream test suite). If 0 files are modified or the upstream test suite is unavailable, the verifier returns `REGRESSION_SKIPPED` / `NOT_MEASURED`, never a synthetic PASS.
- **Regression Test:** `tests/test_final_claim_consistency.py::test_regression_verifier_no_fallback` verifies that empty diffs yield `REGRESSION_SKIPPED`.

### Finding 09: `run_agent_validation.py` Fail-Confused Semantic Accounting
- **Severity:** High (P0)
- **Source Path:** `experiments/rcir_v8_5/scripts/run_agent_validation.py`
- **Root Cause:** The script checked `ab_result.get("valid_pairs")` which was nested inside `ab_result["summary"]["valid_pairs"]`, leading to `None` and defaulting status checks.
- **Correction Applied:** Fixed path traversal to `ab_result.get("summary", {}).get("valid_pairs", 0)` and added strict schema assertion.
- **Regression Test:** `tests/test_final_claim_consistency.py`.

### Finding 10: `run_formal_benchmark.py` Defaulting to PASS on Missing Results
- **Severity:** High (P0)
- **Source Path:** `experiments/rcir_v8_5/scripts/run_formal_benchmark.py`
- **Root Cause:** If a stage sub-process exited with code 0 without writing a `*_result.json` file, the orchestrator defaulted the stage status to `PASSED`.
- **Correction Applied:** Hardened stage verifier: if `result.json` is missing or invalid, the stage is marked `FAILED` / `NOT_MEASURED`, regardless of process exit code.
- **Regression Test:** Unit tests in `tests/test_final_claim_consistency.py`.

### Finding 11: Arbitrary Partial Coverage & Windows Paths in ERPNext Feature Closure
- **Severity:** High (P0)
- **Source Path:** `rcir/src/rcir/adapters/frappe_erpnext.py`
- **Root Cause:** `frappe_erpnext.py` assigned arbitrary 0.85 coverage when hooks were not discovered, emitted literal `"framework_registered_hook"` placeholder hashes, and emitted absolute Windows paths (`C:\Users\...`).
- **Correction Applied:**
  1. Unbacked layers strictly receive 0.0 coverage.
  2. Substituted `"framework_registered_hook"` with the genuine SHA-256 hash of `erpnext/hooks.py`.
  3. Normalized all paths to POSIX repository-relative paths (`forward slashes`).
- **Regression Test:** `tests/test_feature_closure.py` (all tests passing).

### Finding 14: React Visualizer Tabs 03 and 05 Runtime Exceptions
- **Severity:** Medium (P1)
- **Source Path:** `rcir/visualizer-react/src/components/Tab03RCIR.jsx`, `Tab05ERPNextScale.jsx`
- **Root Cause:** Tab 03 crashed when accessing `ranked_candidates` instead of `sample_ranked_candidates`. Tab 05 crashed when accessing `preset_rcir_tasks` instead of `preset_queries` and on missing `critical_sources`.
- **Correction Applied:** Implemented fallback field accessors (`ranked_candidates || sample_ranked_candidates || []`) and guarded all optional property accesses. Streamlined Tab 05 into a clean 2-column layout. Verified zero browser console exceptions.
- **Regression Test:** Browser subagent execution and Vite build validation.

### Finding 15: Run Scoping and Artifact Isolation
- **Severity:** Medium (P1)
- **Source Path:** `experiments/runs/`
- **Root Cause:** Historical test runs dumped artifacts into root directories without unique run IDs or isolated export structures.
- **Correction Applied:** Created isolated, run-scoped artifact trees under `experiments/runs/<run_id>/` with dedicated `raw/`, `results/`, `reports/`, and `exports/` directories.

### Finding 16: Unbacked ERPNext Parity Claims
- **Severity:** High (P0)
- **Source Path:** `FINAL_SYSTEM_ASSESSMENT.md`, `showcase/data/erpnext_scale.json`
- **Root Cause:** Initial reports risked conflating 100% structural DocType schema mapping with full runtime behavioral execution parity.
- **Correction Applied:** Explicitly segregated ERPNext metrics into three tiers:
  1. Structural Schema Mapping: 840 DocTypes, 842 Poly features, 712,940 LOC mapped.
  2. Executable Features: Controlled verticals (Sales Invoice, Stock Entry, Payment Entry) executed via `PolyCellRuntime`.
  3. Behavioral Upstream Parity: Classified as `NOT_VERIFIED` / `LOCAL FIXTURE ONLY` due to lack of full live MariaDB/Redis containerized Frappe bench in test environment.
- **Regression Test:** `tests/test_final_claim_consistency.py::test_erpnext_parity_tiers_segregated`.
