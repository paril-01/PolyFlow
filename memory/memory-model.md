# Memory Model

## What Gets Remembered

The engineering memory system tracks:

| Category | Examples | Retention |
|----------|---------|-----------|
| **Architecture** | System design, component boundaries, patterns | Permanent |
| **Requirements** | Functional and non-functional requirements | Permanent |
| **Decisions** | ADRs, technology choices, trade-offs | Permanent |
| **Risks** | Identified risks and mitigations | Until resolved |
| **Constraints** | Technical, business, regulatory constraints | Until changed |
| **Assumptions** | Validated and invalidated assumptions | Permanent |
| **Technical Debt** | Known debt items with remediation plans | Until resolved |
| **Open Questions** | Unresolved engineering questions | Until answered |
| **Performance Budgets** | Response time, throughput targets | Until updated |
| **Security Boundaries** | Trust boundaries, data sensitivity | Permanent |
| **Future Roadmap** | Planned features, architecture evolution | Until completed |

## How Memory is Maintained

1. **Automated capture**: Agents record events as part of their workflow
2. **Periodic review**: Quarterly review of memory for accuracy
3. **Continuous update**: Memory is updated with every significant event
4. **Cross-referencing**: Memory entries link to related artifacts
